## 一、换肤贴图渲染错误：根因与修复（已确认）

**结论：不是数据/预设问题，也不是 CS2 本体问题，是换肤插件 `PlayerKnifeCustomizer` 自己硬编码的内存特征码在 CS2 2026/9/23 更新后失效。**

- 插件用一段写死的 AOB 特征码定位游戏函数 `CAttributeList::SetOrAddAttributeValueByName`，通过它写入皮肤的三个关键属性 `set item texture prefab / seed / wear`。
- 老特征码 `40 53 55 41 56 48 81 EC 90 00 00 00` 在更新后的 `server.dll` 里**匹配 0 处**（我扫描过，当前 server.dll 34,628,248 字节）。
- 特征码失效时插件**不报错退出**：它照样写 `m_nFallbackPaintKit/Seed/Wear`，所以皮肤"看起来换上了"，但决定贴图/图案的属性写不进去 → 就是你看到的**贴图渲染错误**。每次应用都会在日志里留下 `Apply failed ... Invalid function pointer`。

你机器上的日志时间线（`addons/counterstrikesharp/logs/`）：

```
2026-09-22 17:50:39 [INFO] Loaded generation-safe pipeline; signature=true, catalog=2106   ← 更新前，完全正常
2026-09-23 17:31:51 [INFO] Loaded generation-safe pipeline; signature=true, catalog=2106
2026-09-23 17:34:20 [EROR] Apply failed during agent pipeline ...: Invalid function pointer ← 更新当天开始出错
```

同一天 CounterStrikeSharp 自己的 gamedata 也一起炸了（`Failed to find signature for 'CEntityInstance_AcceptInput'`、`SetModel: Invalid function pointer`），这部分你装的 CS2-Bot-Improver 1.4.5/1.4.6 已经修好（带的是 CounterStrikeSharp 1.0.376 + 新 gamedata），**但上游不会替 Local-Arena 改它自己那段特征码**，所以只剩换肤坏了。

**修复**：换成上游当前在用的特征码 `48 89 4C 24 ? 53 41 55 41 56`，用 .NET 10 SDK 以 `CounterStrikeSharp.API 1.0.376` 重新编译。验证：

```
skin plugin signature: new=true old=false -> OK
server.dll (34628248 bytes): signature matches=1 -> OK      ← 新特征码在当前 server.dll 里唯一匹配
```

上游就是用同一段特征码给机器人写皮肤（你的机器人皮肤一直正常，等于已经侧面验证过这段特征码可用）。

顺带纠正一个细节：印花集家族是 **AK-47 / AWP / 沙漠之鹰 / M4A1消音版(60) / USP消音版(61)**，**没有 M4A4 印花集**；你看到的应该是 M4A1消音版 | 印花集。它们共用同一条写入管线，所以会被同一个 bug 一起影响。

## 五、内置「在线更新」指向本地源：**已实测排除**（附证据）

你选了"先试纯本地 https + 自签证书"，我做了完整尝试，结论是**这条路走不通**，证据如下：

1. **http 直接被拒**：把面板地址指向 `http://127.0.0.1:8791/...` 后，面板日志是
   `builder error for url (http://...)` —— 面板的 HTTP 客户端用 `reqwest` 且 `https_only(true)`（exe 里就有 `URL scheme is not allowed` 这个字符串），非 https 在构造请求时就被拒。
2. **https + 自签证书也被拒**：我给 `localhost` 签了证书（SAN=localhost，KeyUsage 含 Certificate Signing），用 `certutil -user -addstore Root` 装进**当前用户的受信任根**，本地服务确实起来了，面板也确实连上了（服务端看到 TCP 连接），但握手立刻失败：

   ```
   TLS client error: ERR_SSL_TLSV1_ALERT_UNKNOWN_CA ... tlsv1 alert unknown ca (SSL alert number 48)
   ```

   —— 面板发出的是 `unknown ca` 警报，而服务端**从未收到任何 HTTP 请求**。说明面板的 TLS 栈（rustls）**不读 Windows 证书存储**，用的是自己内置的公共根证书列表，所以本机自签证书无论怎么装都不会被接受。（另外当前会话没有管理员权限，`LocalMachine\Root` 也装不了；不过按上面的现象，装了也没用。）
   试用结束后我已把这个自签根证书从你的用户证书存储里**删除**（已确认剩余 0 个），`release\keys\cert.*` 仅作为记录留着，不再受信任、也不再使用。

**因此，内置在线更新只可能指向"有公共 CA 证书的 https 主机"** —— 也就是你自己的 GitHub Release。步骤（我可以代做，只要告诉我 owner/repo）：

1. 面板的地址是编译进 exe 的**定长字符串**：`https://github.com/<owner>/<repo>/releases/latest/download/latest.json` 必须**正好 77 字节**，即 **owner 长度 + repo 长度 = 20**（官方是 `numakkiyu`(9) + `Local-Arena`(11)）。比如你的用户名是 8 字符，就取 12 字符的仓库名。
2. 建仓库 → 建 Release，tag 用 `v1.4.6.1` → 上传这三个文件（完整包想放也行）：
   `LocalArena-plugin-v1.4.6.1-windows.zip`、`latest.json`、`latest.json.sig`
3. 如果 owner/repo 与占位符不同，先重新生成签名清单（把里面的下载地址换成你的）：
   ```
   node release\tools\make-feed.js 1.4.6.1 1.4.6.1 https://github.com/<owner>/<repo>
   ```
   然后重新上传 `latest.json`、`latest.json.sig`。
4. 给面板打补丁（脚本会先校验长度，并把原 exe 备份为 `LocalArena.exe.before-patch.bak`）：
   ```
   node release\repatch-panel.js https://github.com/<owner>/<repo>
   ```
5. 打开面板 → 设置 → 在线更新 → 手动检查更新。清单里插件版本是 1.4.6.1、与你已安装的一致，所以会显示"已是最新"；想亲眼看到它工作，可以临时把 feed 版本写成 1.4.6.2 再检查（会显示有可用更新，点更新即可装同一份负载）。
   `latest.json` 里的"面板"组件我特意固定在 1.4.3.3，面板永远不会尝试替换自己。
6. 不想折腾的话：以后升级就是把 `LocalArena-plugin-vX-windows.zip` 解压覆盖到面板目录再用面板的"安装/修复"落到游戏目录，面板不会来烦你（版本号已对齐）。

### 网络代理（重要）

你机器上开着系统代理（`127.0.0.1:7890`），但面板的 HTTP 客户端**只认 `HTTP_PROXY`/`HTTPS_PROXY` 环境变量，不认 Windows 系统代理**，所以直接双击 `LocalArena.exe` 时"在线更新"会报 `Cannot contact GitHub update service`。
